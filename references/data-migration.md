# 数据层迁移（按数据类型）

> 红线：**不打包运行中的数据库容器目录**。文件可能正在写入，复制出来的是损坏数据。

| 数据类型 | 迁移方式 | 验证 |
| --- | --- | --- |
| 应用代码 | 从 GitHub 拉取（含 Dockerfile/compose） | commit/tag 与部署记录一致 |
| PostgreSQL | `pg_dump -Fc`（一致快照）或复制槽做不停机同步；恢复用 `pg_restore` | 恢复后 `COUNT(*)` 关键表 + 抽样比对 + 应用冒烟 |
| MySQL/MariaDB | `mysqldump --single-transaction` 或 XtraBackup | 同上 |
| Redis | RDB `BGSAVE` + AOF 或主从同步 | 键数量级一致 |
| SQLite | 停止写入后复制文件（或 `.backup`） | 校验和一致 |
| Docker volumes | 按内容分类后走对应工具（DB 用原生备份，静态文件用 rsync） | 逐项核对 |
| 用户上传文件 | rsync（停止写入或两次 rsync 收敛） | 文件数与大小一致 |
| 环境变量/密钥 | 安全通道传输；新机落盘 600 权限；**不进仓库** | 启动成功 + 无密钥在日志 |
| HTTPS 证书 | **优先新机重新申请**；ACME 证书不搬私钥 | 新证书签发成功 |
| DNS | 服务商 API 或手动；先降 TTL 再切换 | 解析收敛到新 IP |

数据库迁移检查表：

1. 选一致性工具（按引擎）；2. 备份到旧机之外（异地/新机）；3. **恢复演练**（临时实例）验证备份可打开；
4. 记录备份时间点；5. 切换前做增量（避免窗口内丢单）；6. 恢复后跑应用级校验，不只跑 `COUNT`。

需要不停机时（场景 A）：数据库用复制/逻辑订阅做**并行同步**，切换前停写 → 追平 → 切连，
而不是把"备份导入"当零停机方案。
