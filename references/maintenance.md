# 技能维护手册（vps-migrator）

维护动作四类：追加、合并、提升、废弃。

## 1. 什么时候写

- 迁移/重建/恢复踩到新坑（尤其数据或切换窗口出问题）；
- 一个判断被推翻（例：以为能停 1 小时，实际需要不停机）；
- 拿到真实数据（备份体积/耗时、DNS 收敛时间）；
- 工具变化（compose v1→v2、证书签发策略）；
- 用户明确偏好（停机容忍、密钥管理方式）。

不写：通用常识、官方文档能查到的、真实密钥/地址/域名。

## 2. 怎么写

```markdown
### L-编号 一句话结论（动词开头）
- 日期：YYYY-MM-DD｜来源：真实项目（哪次迁移）/ 推理｜场景：A/B/C/D
- 结论：<一句话，能直接指导决策>
- 为什么＋落地：<原因 + 落地，3 行以内>
```

## 3. 去重 / 提升 / 废弃

- 同主题在原条目补充；冲突时新条目覆盖，旧条目标 `[deprecated by L-xxx]`；
- 同主题 ≥2 条或触及不可妥协项 → 提升进 playbook/data-migration/infrastructure，保留溯源；
- 外部前提变化（如全面换 k8s）→ 对应段落标 `[deprecated]`，不静默删除。

## 4. 同步与版本

**唯一上游：独立开源仓库（vps-migrator）。** `platform-kit/skills/` 为 vendored 副本，
`~/.codex/skills/` 为安装副本——编辑只在上游，单向同步。

## 5. 自检清单

1. frontmatter `name` 与目录名一致、`description` 能区分场景；
2. SKILL.md 引用文件都存在；3. 无待办标记；4. 新增条目未含机密；5. 副本已同步；
6. 新增原则/概念前查 agent-skills-index 的 `concept-map.md`：已有则引用不复制，新概念先登记权威位置。
7. 决策回填与提升规则见 agent-skills-index 的 `conventions/knowledge-evolution.md`（证据等级：真实反例 > 推理）。
